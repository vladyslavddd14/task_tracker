# Тестування

Усі тести проходять локально: 247 backend-тестів і 77 frontend-тестів.

## Запуск

```bash
# backend: інтеграційним тестам потрібен запущений Docker (Testcontainers)
cd backend
dotnet test

# frontend
cd frontend
npm test
```

Окремі проєкти: `dotnet test tests/TaskTracker.Domain.Tests` (також `…Application.Tests`, `…Api.IntegrationTests`).

## Рівні

| Рівень | Проєкт | Кількість | Інструменти |
|---|---|---|---|
| Domain | `TaskTracker.Domain.Tests` | 42 | xUnit, FluentAssertions |
| Application | `TaskTracker.Application.Tests` | 101 | + NSubstitute (підміна репозиторіїв) |
| Інтеграційні | `TaskTracker.Api.IntegrationTests` | 104 | `WebApplicationFactory`, Testcontainers (`postgres:16-alpine`) |
| Frontend | `frontend/src/**/*.test.ts(x)` | 77 | Vitest, React Testing Library, jsdom |

## Що перевіряється

### Domain
Обрізання й відхилення порожньої або задовгої назви; `CompletedAt` при переході в `Done` та його очищення; усі шість переходів статусів із записом `StatusTransition`; відсутність запису при тому ж статусі; визначення «прострочено»; прогрес підзадач і ліміт 50; перевпорядкування; заміна тегів; upsert значень полів; шаблони профілів.

### Application
- **Фільтри** над списком у пам'яті: статуси, пріоритет, теги, усі режими дедлайну, діапазон, пошук (регістр, кирилиця, нотатки), перетин умов («прострочені з тегом `work` за пріоритетом»), власні поля, сортування;
- **Валідатори:** email, пароль (8–100), назви, теги, поля, `pageSize` 1–200, календарний діапазон;
- **Сервіси** з підміненими репозиторіями: порожня назва не зберігається, чужий ресурс дає `NotFound`, зміна статусу пише перехід, перенумерація колонки, шаблони без дублікатів, хешування пароля, `Conflict` при дублі email;
- **Час:** «сьогодні» залежить від часового поясу.

### Інтеграційні (реальний PostgreSQL, міграції застосовуються при старті)
- реєстрація, вхід, `401` без токена, пароль зберігається лише як солоний хеш;
- CRUD задач, порожній заголовок (`400` + поле `title`), історія переходів, довжини;
- **ізоляція користувачів:** чужа задача, тег чи поле дають `404` на читання, зміну, переміщення й видалення, списки порожні, прив'язати чужий тег не можна;
- фільтри, сортування, пагінація, «Сьогодні» у різних часових поясах, календар;
- підзадачі (ліміт 50, перевпорядкування), Kanban (порядок зберігається, перенумерація при тісних позиціях);
- теги й власні поля (унікальність, валідація за типом, видалення), шаблони профілів;
- **каскадні видалення** перевіряються прямо в БД;
- ідемпотентність міграцій, демо-сид, виявлення конкурентних змін (`xmin`).

### Frontend
Валідація (порожня назва, довжини, email, пароль, значення полів); арифметика дат (літній час, кінець місяця, тиждень з понеділка, часові пояси); логіка дошки (позиції між сусідами, колонки); діапазони календаря; HTTP-клієнт (Bearer, `401`, problem details, `204`); перетворення фільтрів на параметри; форми входу й реєстрації; швидке додавання задачі; перемикач виглядів і запам'ятовування вибору; **безпека Markdown** (скрипти, обробники подій, `javascript:`, iframe, форми).

## Не покрито автоматично

E2E-сценарій (Playwright) відсутній. Його частково замінюють інтеграційні тести та ручна перевірка: реєстрація, створення, зміна статусу, фільтр, `docker compose down` / `up`, перевірка, що дані на місці. Візуальний вигляд і перетягування мишею перевіряються вручну.
