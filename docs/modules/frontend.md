# Модуль Frontend (`frontend/`)

Single-page застосунок на React 18 + TypeScript (Vite). Бібліотеки: React Router, TanStack Query, dnd-kit, react-markdown (remark-gfm + rehype-sanitize). Календар написаний власноруч.

## Структура

```text
src/
  api/        client.ts (HTTP, токен, ApiError), endpoints.ts (методи API), types.ts
  components/ Modal, ConfirmDialog, Badges (пріоритет, теги, прогрес), Feedback,
              MarkdownView, AppLayout, ThemeProvider
  features/
    auth/      AuthContext, RequireAuth, LoginForm, RegisterForm
    tasks/     queries.ts, filters.ts, QuickAdd, TaskFilters, TaskList, TaskRow,
               TaskDetailsModal, TaskForm, SubtaskList, NotesEditor,
               CustomFieldInputs, ViewSwitcher
    board/     Board, boardLogic
    calendar/  Calendar, calendarLogic
    tags/      TagManager
    settings/  ProfileSettings (профіль, шаблон, пароль), CustomFieldManager
  pages/      AuthPages, TodayPage, TasksPage, SettingsPage
  hooks/      useLocalStorage, useDebounce, useViewMode, useTheme
  i18n/       uk.ts (усі тексти), index.ts
  lib/        dates.ts, validation.ts, errors.ts
  styles.css  глас-морфізм, світла й темна теми
```

## Маршрути

| Шлях | Сторінка |
|---|---|
| `/login`, `/register` | вхід і реєстрація (із вибором шаблону профілю) |
| `/today` | «Сьогодні»: стартова сторінка після входу |
| `/tasks` | список / Kanban / календар зі спільною панеллю фільтрів |
| `/settings` | профіль, шаблон, теги, власні поля, пароль, тема |

Решта шляхів перенаправляється на `/today`, захищені сторінки на `/login`. Деталі задачі відкриваються у вікні за параметром `?task=<id>`, тому на задачу можна зробити посилання.

## Автентифікація

`AuthContext` зберігає користувача та стан (`loading`, `authenticated`, `anonymous`). Токен лежить у `localStorage` (`tt.token`), `request()` додає його до кожного запиту. Якщо захищений запит повертає `401`, токен очищається, кеш скидається, і `RequireAuth` перенаправляє на `/login`. `401` від самих `/auth/*` розглядається як «невірні дані», а не як завершена сесія. При вході та виході кеш запитів очищається, щоб не показувати дані попереднього акаунта.

## Робота з даними (TanStack Query)

Усі ключі запитів задач починаються з `['tasks', …]`, тому одна інвалідація оновлює список, дошку, календар «Сьогодні» і деталі. Ключі: `list`, `board`, `today`, `calendar`, `undated`, `detail`.

- **Помилки:** 4xx не повторюються, мережеві й серверні повторюються двічі.
- **Дошка** завантажує всі задачі, сторінка за сторінкою по 200.
- **Оптимістичні оновлення:** `useMoveTask` одразу переміщує картку в кеші, а при помилці повертає знімок і показує повідомлення; після завершення дані перечитуються.
- **Зміна дедлайну в календарі** (`useSetDeadline`) спершу завантажує задачу, бо `PUT` замінює всі поля.

## Фільтри

`TaskFilters` (стан інтерфейсу) перетворюється на параметри API функцією `filtersToParams`. Пошук застосовується з затримкою 300 мс. Однакові фільтри діють у списку, на дошці та в календарі. Некоректний діапазон дат (до < від) не надсилається, доки користувач його не виправить. Фільтр за власним полем доступний для всіх типів (для прапорця вибір так/ні).

## Список і «Сьогодні»

`TaskList`/`TaskRow`: зміна статусу прямо в рядку, видалення з підтвердженням (`ConfirmDialog`), прострочені задачі виділено червоним, прогрес підзадач показано смужкою. Пагінація по 50. Швидке додавання (`QuickAdd`): Enter створює задачу; порожню назву відхиляє перевірка на клієнті. На сторінці «Сьогодні» нова задача отримує дедлайн на сьогодні (за поясом користувача), інакше її не було б видно.

## Деталі задачі

`TaskDetailsModal` поєднує:
- `TaskForm`: усі поля, теги, власні поля (тип поля визначає елемент вводу, значення перевіряються за типом);
- `SubtaskList`: додавання, перейменування, відмітка, перевпорядкування, видалення; коли всі підзадачі виконані, пропонується «Позначити задачу виконаною» (статус сам не змінюється);
- `NotesEditor`: вкладки «Редагувати» / «Перегляд»;
- історію статусів із часом у поясі користувача.

### Markdown і безпека
`MarkdownView` використовує `remark-gfm` (таблиці, чекбокси, код, цитати) і `rehype-sanitize`. Сирий HTML не перетворюється на елементи (`rehype-raw` не підключено), небезпечні атрибути та `javascript:`-посилання вилучаються, посилання відкриваються з `rel="noopener noreferrer nofollow"`. Це покрито тестами.

## Kanban (`features/board`)

Три колонки, `dnd-kit` з Pointer- та Keyboard-сенсорами (Пробіл підняти, стрілки перемістити, Пробіл опустити). Чиста логіка в `boardLogic.ts`:

- `groupByStatus` розкладає задачі за колонками та позиціями;
- `resolveDropTarget` визначає, куди скинуто картку (на іншу картку або в кінець колонки);
- `computeMove` обчислює нову позицію як середину між двома сусідами (або ±1000 на краях), тож змінюється лише одна картка.

Для кліку без перетягування сенсор має поріг 6 px.

## Календар (`features/calendar`)

Режими «Місяць» (сітка з 5–6 тижнів) і «Тиждень», тиждень починається з понеділка. Навігація: попередній/наступний період і «Сьогодні». Задачі стоять у клітинках за дедлайном, кольорова смужка відповідає пріоритету, виконані приглушені, прострочені виділені. Панель «Без дати» показує задачі без дедлайну. Задачу можна перетягнути на день, щоб змінити дедлайн. `calendarLogic.ts` містить `getVisibleRange`, `shiftAnchor`, `groupByDeadline`.

## Дати

Дедлайн це рядок `YYYY-MM-DD`; уся арифметика виконується через UTC-компоненти (`lib/dates.ts`), тому літній час і пояс браузера не зсувають дату. «Сьогодні» обчислюється за поясом користувача (`todayInZone`), а часові мітки з API форматуються в його поясі.

## Локалізація

Усі тексти інтерфейсу лежать в `src/i18n/uk.ts` (з функціями для підстановок, як `t.tasks.pageOf(page, pages)`), а активну мову вибирає `src/i18n/index.ts`. Щоб додати мову, створіть файл тієї ж форми та змініть один рядок в `index.ts`. Помилки API показуються українською через `describeError`.

## Валідація

`lib/validation.ts` повторює правила бекенда (довжини, email, пароль, значення власних полів). Це зручність для користувача, а джерело істини залишається на сервері.

## Тема

Світла та темна теми керуються атрибутом `data-theme` на `<html>`. Без збереженого вибору береться системна тема, вибір запам'ятовується в `localStorage`. Стиль глас-морфізм: градієнтний фон, матові напівпрозорі панелі з `backdrop-filter`, запасний суцільніший фон для браузерів без його підтримки. Адаптивність від 360 px, дошка прокручується горизонтально.

## Доступність

Підписи до полів, `aria-invalid`/`aria-describedby` для помилок, `role="dialog"` із пасткою фокуса та поверненням фокуса, `aria-pressed` у перемикачах, `role="progressbar"`, посилання «Перейти до вмісту», повага до `prefers-reduced-motion`.
